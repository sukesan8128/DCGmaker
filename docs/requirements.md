# DCGmaker 要件定義

## 目的

DCGmakerは、デジタルカードゲーム風のオリジナルカード画像を作成するローカル向けツールである。
ハースストーンやシャドウバースのような「コスト、攻撃、HP、イラスト、装飾枠、詳細ウィンドウ」を持つカードを、入力フォームから生成し、PNG画像として書き出せることを目標とする。

既存ゲームのカードデザイン、ロゴ、UI、固有フォント、固有アイコンをそのまま模倣せず、DCGらしい構成要素を使った独自デザインとして実装する。

## 想定ユーザー

- オリジナルDCGやボードゲームのプロトタイプを作る開発者
- カード能力案を画像として共有したい企画者
- TRPG、同人ゲーム、個人制作ゲーム向けにカード画像を量産したい制作者

## MVP範囲

最初の実装では、1枚のカードを画面上で編集し、即時プレビューし、PNGとして保存できる状態を完成条件とする。

### カード共通項目

- カード名
- カード種類
- コスト、マナ
- カード本文
- フレーバーテキスト
- レアリティ
- クラス、属性、勢力などの分類
- イラスト画像
- カード種類、レアリティに対応したカード枠
- 書き出しサイズ

### カード種類

MVPでは以下を扱う。

- モンスター
  - コスト、攻撃、HPを表示する
  - DCGのユニット、フォロワー、ミニオン相当
- スペル
  - コストと効果本文を扱う
  - 攻撃、HPは表示しない
- フィールド
  - コストと効果本文を扱う
  - 場に残るカードを表す
  - 耐久値または持続ターンは将来拡張とする

将来拡張として、装備、トークン、リーダー、クエスト、アーティファクトなどを追加できる設計にする。

### ステータス

- コスト
  - 0以上の整数
  - すべてのカード種類で表示する
- 攻撃
  - 0以上の整数
  - モンスターで表示する
- HP
  - 1以上の整数
  - モンスターで表示する

### カード枠

- カードごとの自由な枠色変更は行わない
- カード種類ごとに、モンスター、スペル、フィールド用の枠素材を用意する
- 各カード種類に対して、ブロンズ、シルバー、ゴールド、レジェンドの4レアリティ枠を用意する
- 枠素材は四角形を基調にし、過度な流線型や強すぎる立体感を避ける
- 本文の可読性を損なわないよう、カード効果とフレーバーテキストは詳細ウィンドウ側に表示する

### イラスト

- ユーザーがローカル画像をアップロードできる
- 未指定時はグラデーションまたはプレースホルダーを表示する
- 画像はカード上部のアート領域にトリミングして表示する
- 画像の位置調整、拡大縮小は将来拡張とする

### プレビュー

- 入力変更を即時にカードプレビューへ反映する
- カード比率は縦長の標準フォーマットとする
- MVPの基準サイズは 744 x 1038 px とする
- 画面表示ではレスポンシブに縮小する
- カードのみ書き出し時は基準サイズでPNGを生成する
- 全体書き出し時は 1600 x 900 px の横長PNGを生成する
- 全体選択時は、画面上のプレビューも横長PNGと同じ構成で表示する
- カード効果とフレーバーテキストはカード本体には載せず、カード横の詳細ウィンドウに表示する
- 分類、カード効果、フレーバーテキストは、それぞれ詳細ウィンドウで表示/非表示を切り替えられる
- 全体出力の詳細ウィンドウには、カード本体で確認できるマナ、攻撃、HPを重複表示しない
- 狭い画面では詳細ウィンドウをカード下に配置する

### 書き出し

- PNG形式でダウンロードできる
- 書き出し形式はカードのみ、全体から選択できる
- 書き出し形式はPNG書き出しボタンの近くでも選択できる
- 全体では、横長スマートフォン画面相当のキャンバスにカード、背景、詳細ウィンドウを合成する
- ファイル名はカード名から生成する
- カード名が空の場合は `dcg-card.png` とする

## 画面要件

MVPは1画面構成とする。

- 左側または上部に編集フォームを配置する
- 右側または下部にカードプレビューを配置する
- デスクトップではフォームとプレビューを横並びにする
- デスクトップでは左側の編集フォーム幅をドラッグで狭められる
- モバイル幅では縦積みにする

入力UIは以下を使用する。

- テキスト入力: カード名、分類、フレーバーテキスト
- 数値入力: コスト、攻撃、HP
- セレクトまたはセグメント: カード種類、レアリティ
- チェックボックス: 分類表示、カード効果表示、フレーバー表示
- ファイル入力: イラスト画像
- ボタン: PNG書き出し

## デザイン要件

- DCGカードらしく、コスト、攻撃、HPが一目で読めることを優先する
- 文字が枠からはみ出さない
- 長いカード本文は折り返し、必要に応じて文字サイズを調整する
- 日本語と英数字が混在しても破綻しない
- 既存DCGの固有UIを直接コピーしない
- カード枠は生成画像素材を使い、金属、宝石、革などを連想させる装飾感を持たせる
- レア度の違いは、カード枠色そのものではなく、宝石、縁取り、細い装飾線、光彩などの装飾色で表現する
- レア度はブロンズ、シルバー、ゴールド、レジェンドの4段階とする
- レジェンドは白金を基調に、シアン、薄紫、淡いピンクが反射する虹彩の装飾で表現する
- カード下部のレアリティ装飾は宝石のみとし、レアリティ名の文字は表示しない
- マナ、攻撃、HPは宝石面と金属縁を持つ装飾プレートとして表示する
- 編集UIは読みやすい明色ベースにし、凝った背景や詳細ウィンドウ表現は主に画像出力側で行う

## 非機能要件

- ローカル環境で動作する
- MVPではバックエンドを持たない
- 主要ブラウザの最新版で動作する
- 書き出し画像はプレビューと大きくズレない
- 入力値の不正状態でアプリがクラッシュしない
- 生成物はオリジナルカードとして利用できるよう、商用ゲーム固有素材に依存しない

## 推奨技術方針

空のリポジトリから開始するため、MVPは以下の構成を推奨する。

- Vite
- React
- TypeScript
- Canvas 2D API
- CSS Modulesまたは通常CSS

理由:

- フォーム状態とプレビュー更新をReactで扱いやすい
- TypeScriptでカード種類ごとの表示条件を安全に管理しやすい
- Canvas 2D APIを使うと、プレビューとPNG書き出しの差異を抑えやすい
- MVPではサーバー不要で完結できる

## データモデル案

```ts
type CardType = "monster" | "spell" | "field";

type Rarity = "bronze" | "silver" | "gold" | "legendary";

type CardDraft = {
  name: string;
  type: CardType;
  cost: number;
  attack: number;
  hp: number;
  text: string;
  flavorText: string;
  showClassName: boolean;
  showEffectText: boolean;
  showFlavorText: boolean;
  rarity: Rarity;
  className: string;
  artworkDataUrl?: string;
};
```

## 受け入れ条件

- モンスターカードで、コスト、攻撃、HP、カード名、イラスト、種類別/レアリティ別の枠が表示される
- スペルカードに切り替えると、攻撃とHPが表示されない
- フィールドカードに切り替えると、攻撃とHPが表示されず、効果本文は詳細ウィンドウ側で扱われる
- 分類、カード効果、フレーバーテキストはカード本体ではなく、プレビュー横の詳細ウィンドウに表示される
- カード種類やレアリティを変更すると、対応する生成枠素材へ即時反映される
- ローカル画像を指定すると、カードのアート領域に表示される
- PNG書き出しボタンで画像を保存できる
- PNG書き出しはカードのみと全体を切り替えられる
- 全体PNGは 1600 x 900 px で出力される
- 長い日本語本文でもカード外へはみ出さない
- デスクトップ幅とモバイル幅の両方で編集できる

## MVP後の拡張候補

- 複数カードの保存、一覧、再編集
- JSONインポート、エクスポート
- CSVからの一括カード生成
- 複数テンプレートの切り替え
- レアリティごとの追加装飾
- イラストの位置、拡大率調整
- 透過PNG、印刷用PDFの出力
- カードセット単位の管理
- ランダムカード生成
- AI画像生成連携

## 実装ステップ案

1. Vite + React + TypeScriptでアプリを作成する
2. `CardDraft`の型と初期値を定義する
3. 編集フォームを作成する
4. Canvasベースのカード描画関数を作成する
5. プレビューCanvasへ即時描画する
6. 画像アップロードをData URLとして扱う
7. PNG書き出しを実装する
8. モバイル表示と長文表示を調整する
9. ビルドと簡易動作確認を行う
